# Contract changes

Deviations from `API_CONTRACT.md` (v0.2). Each has a reason. Source: `BUILD_PLAN.md` section 3 plus review decisions.

| # | Change | Reason |
|---|---|---|
| 1 | `narrative` is a deterministic template over `accepted`/`edited` events, rebuilt on every GET | Fast, free, stable; guarantees rejected events never reach the form |
| 2 | `PATCH /gaps/{id}` with `value`: if the gap has `input.field_key`, write the value to that form field as `user_entered` and resolve the gap | Matches prototype behaviour; one round trip |
| 3 | `Run.stale: boolean`, true when evidence arrives after `started_at` | UI can tell the caseworker to re-run |
| 4 | Run terminal status: `failed` if a step failed; `needs_review` if a step is `needs_input` or `incomplete` (see 41), any event `pending`, or a blocking gap is open; else `done` | Contract left it undefined |
| 5 | `Run.usage: { input_tokens, output_tokens, est_cost_usd, duration_ms }` | Performance and cost evidence |
| 6 | New `POST /runs/{run_id}/answer` with `{ step_key, answer }` (body changed to `{ answer }`, see 29) | Resume a run paused by `ask_caseworker` |
| 7 | `EvidenceItem.sha256` is of the original bytes; the EXIF-stripped copy is a separate derived blob | Chain of custody |
| 8 | `POST /cases/{id}/package` errors: **409** when case state blocks it (open blocking gaps, tenant not attested); **422** when the body lacks caseworker attestations. Both return `{ detail: { reasons: string[] } }` | Prototype used 400 and a string `detail`; clearer split |
| 9 | Every by-id handler checks `obj.case.org_id == user.org_id`; other orgs get 404 | Object-level authorization |
| 10 | New `POST /auth/login` returning an httpOnly session cookie. M0 uses a dev-stub user; real login in M1 | Auth |
| 11 | Intake links: `Intake.url` is `string \| null`. The raw link (`secrets.token_urlsafe(32)`) is returned only by `POST /cases/{id}/intake-link`; every GET returns `null`. The DB stores only sha256 + expiry + revoked flag (table `intake_token`). Re-sending creates a new token and revokes all earlier ones; revoked, expired and unknown tokens all return the same 404 | Tokens are not recoverable from the database or from case reads |
| 12 | `PATCH /cases/{case_id}/form-draft/fields/{key}` (was `/form-draft/fields/{key}`) | Field keys repeat per case, so the case must be in the path |
| 13 | `Package` gains `version: number` and `sha256: string` (of the zip). Every `POST /cases/{id}/package` creates a new version; rows are never overwritten. The zip is stored content-addressed (sha256) outside the database; the row keeps `sha256` + `storage_key` | Chain of custody; rebuild history |
| 14 | New `GET /cases/{id}/package/download[?version=N]`: latest version unless `N` given; 404 for unknown version or no package; org-checked; also sends `X-Package-Sha256` | Contract had no way to fetch the package |
| 15 | `POST /auth/logout` returns `{ ok: true }` and clears the cookie; `POST /auth/login` body `{ email, password }` returns `User` | Completes #10 |
| 16 | `PATCH /timeline/{id}`: an edit to title/description/date with no `review_status` sets `edited`; a date is stamped `basis: "user"` only when its value or precision actually changed; `caseworker_note: null` clears, omitting it keeps. `review_status` is optional (contract listed it as required); a no-op edit changes nothing, and a rejected event needs an explicit `review_status` to come back. `date.value` must be a valid date for its precision (422 otherwise) | UI resends the unchanged date on every edit |
| 17 | Stage rules: `POST /gaps/{id}/tenant-request` sets `waiting_tenant`; `POST /intake/{token}/submit` recomputes the stage (normally back to `needs_review`); other mutations recompute it, keeping `waiting_tenant` only while a request is outstanding and always keeping `hearing_scheduled` | Caseload shows when a case needs attention again |
| 18 | `POST /intake/{token}/submit` in M1 records the attestation only (no files); 422 `{ detail: { reasons } }` unless both `attest_genuine` and `consent_share` are true. Response `{ ok: true }` | Files arrive in M2 |
| 19 | `PATCH /gaps/{id}` reopening a resolved gap clears the form value that gap wrote (field returns to `missing`); `value` requires `status: "resolved"` and a gap with an `input.field_key` (422 otherwise) | Keeps form and gaps consistent |
| 20 | `PATCH /cases/{id}/form-draft/fields/{key}` with an empty value reopens the gap it had resolved. The stage counts empty required fields like open blocking gaps, so stage and package gating agree | Found by tests: stage said `ready_to_file` while the package refused |
| 21 | `POST /cases/{id}/package` with no body or missing attestations also answers 422 `{ detail: { reasons } }`; a narrative line with no sources has no trailing `[]` | Consistent error shape |
| 22 | `PATCH /timeline/{id}` to `accepted` or `edited` (explicit or implied by an edit) on an event with no sources returns 422 `{ detail: { reasons: ["needs at least one source"] } }`; rejecting, resetting to pending and note-only changes still work. The form narrative also leaves out any unsourced event | API_CONTRACT design rule 2: no source, no fact |
| 23 | `POST /cases/{id}/evidence` takes field `file` repeatable and returns `EvidenceItem[]` | The UI sends every picked file in one request |
| 24 | Uploads are checked before anything is stored. More than 20 files, a file over `MAX_UPLOAD_BYTES` (25 MB), or a body above 20 × 25 MB + 1 MB answers 413 (a declared `Content-Length` before the body is read; a chunked body as it arrives, cut off at the limit), a type outside JPG, PNG, HEIC, PDF and TXT answers 415, both as `{ detail: { reasons } }`, and the whole request is refused. `format_check.action: "rejected"` is not used | Nothing half-stored; the type is read from the file's bytes, never its name or Content-Type |
| 25 | A file already on the case (same sha256) comes back as its existing item: no second row, label or blob. `POST /intake/{token}/files` counts it in `received` | Unique `(case_id, sha256)`; re-sending the same photo is common |
| 26 | New evidence marks earlier runs `stale: true` (rule #3). A tenant upload also sets `intake.status` to `files_received` and `intake.last_upload_at` | Rule #3 needed a trigger; intake status had no writer |
| 27 | `POST /intake/{token}/files` answers 404 for an unknown, revoked or expired link, like `GET /intake/{token}`. Both upload routes share `UPLOAD_RATE_LIMIT` | Nothing to probe; tenant links are public |
| 28 | A tenant upload that adds at least one new file clears `intake.tenant_attested_genuine` and `tenant_attested_at`, and logs it, so the package is blocked (409) until the tenant confirms again. The intake page sends the files and then the confirmation, so its normal flow confirms again. Caseworker uploads and re-sent duplicates leave it | The confirmation covered the files sent before it |
| 29 | `POST /runs/{run_id}/answer` takes `{ answer }` only (1 to 500 characters), because a run has one paused step at a time. 404 for another org's run, 409 when the run is not `needs_input` or the pause was already answered, 422 `{ detail: { reasons } }` for an invalid answer, and the run stays paused. The `ask_caseworker` question can carry an optional field key, kept on the server with the paused step and not a field of `Run` (it shows only in the `ask_caseworker` call's input in `tool_calls`); only `hearing_date` is defined. For it the answer is parsed (`YYYY-MM-DD`, or `Nov 21, 2026` / `21 November 2026`; a real date from 2020 to 2099), stored as `Case.hearing_date` and logged. Any other key keeps the answer as text. It also sets `Case.stage` to `hearing_scheduled` and `Case.next_deadline` to `{ date: hearing minus 5 days, label: "Evidence due · hearing <date>" }`, so the caseload priority follows the existing rules. `RunStep.summary` is documented as the question while `needs_input` | The agent has to ask for what only a person knows, such as the hearing date; row 6 named a `step_key` the server does not need; one narrow typed field avoids parsing free text elsewhere |
| 30 | `TimelineEvent.flags[].type` gains `"conflict"`. The agent's `flag_conflict` tool adds one flag per call, with the message `Sources disagree: <reason>`, and still appends `Conflict noted: <reason>` to `strength_reasons`. A conflict flag does not change `strength`, which stays the rules code's | A conflict the agent noted was only in `strength_reasons`, which the review screen hides whenever an event has flags, so the caseworker could not see it |
| 31 | `CaseSummary` gains an optional `analysed` boolean: true once a run has completed (`done`, or `needs_review` with `finished_at` set) or an event is accepted or edited, false otherwise. `POST /cases/{id}/package` answers 409 with `No analysis has been completed for this case yet. Run the analysis first.` when there is no completed run, and `No timeline events have been accepted yet. Review the timeline first.` when no event is accepted or edited (both are listed when both apply; the 422 for a missing attestation still comes first). The case `stage` rules are unchanged | A case with no analysis showed `ready_to_file` and `No open items`, and the package checklist was green with nothing in it |
| 32 | `POST /runs/{run_id}/answer` for the `hearing_date` field also answers 422 `{ detail: { reasons: ["That date has passed. Enter the upcoming hearing date."] } }` for a date before today (UTC); today itself is accepted, and the run stays paused, as for any invalid answer. Other questions are unaffected. The conflict flag message from `flag_conflict` is no longer cut at 100 characters (the input limit, 500, applies) | A hearing date typed in the past would set the stage and an evidence deadline that has already gone; a conflict note was cut mid-quote |
| 33 | `Run.usage.est_cost_usd` is priced with the model actually used (`LLM_MODEL`, else the default), from a list-price table in `services/agent/llm.py` (Haiku 5.5, Sonnet 5.5, Opus 5.5, Fable 5.2; cache reads at each model's own price, writes at 1.25 times input). It is `null` when the model is not in the table, or when one request's prompt exceeded Haiku 5.5's 100K-token rate card (the dearer card is not in the table). `Run.usage.model` (optional string) names the model it was priced with. Earlier runs, stored before this change, keep their old number and have no `model` | The figure was always the default Sonnet price, so a Haiku run showed about 20 times its real cost; an unknown model should say so, not show a wrong number |
| 34 | `GET /cases/{case_id}/case-brief` returns a PDF for the caseworker: case summary, timeline (rejected events left out), evidence index sorted by type then date, and open gaps. Each statement names the upload it came from (label and locator); one no upload supports says NEEDS CASEWORKER VERIFICATION, and the count and a checklist are in the document (what they cover: see 41). Timeline excerpts are checked again against the stored text. `caseworker_note` is never included. Nothing is stored or changed. 409 until a run has completed | The caseworker needed one document after the agent finished, with every claim traceable to a file |
| 35 | New endpoint `POST /cases` (issue #41), body `CaseCreate` `{ tenant_name, tenant_language, unit, title }`, returns `Case`. The org and the assignee are the signed-in caseworker's, never from the body; `dispute_type` is `maintenance`, `stage` `waiting_tenant`, the intake `not_sent`, `synthetic` true, `has_demo_data` true (it has a case view, so the caseload opens it, like the live-demo case); the form name and disclaimer are the seeded case's. Strings are trimmed and must not be blank: tenant name up to 120 characters, unit up to 200, title up to 120. Control characters become spaces and invisible format characters (zero-width, byte-order mark, bidi overrides) are removed, so the stored text can differ from what was sent; a value with nothing visible left is blank. A `<` (or its full-width and small forms) is refused with a reason, not stored escaped. The caseload's `priority_reason` for a `waiting_tenant` case whose link was never sent is "Intake link not sent yet." `tenant_language` is one of `en`, `zh`, `fr`, `es`, the languages the tenant page has text for (no `ar` yet). A bad body answers 422 `{ detail: { reasons } }`, one plain reason per field, as `/runs/{id}/answer` does; extra fields (`org_id`, `stage`) are refused. The activity log gets "Created the case" | Cases came only from the seed: the hosted demo read as a fixed demo, and the live-demo case was fresh only once |
| 36 | The `draft` step (issue #40) is an agent loop, not the deterministic template `BUILD_PLAN.md` planned (the extracted facts carry no field key). Its one write tool fills a form field only while it is `missing`, never the `remedy` field and never one the caseworker cleared after a draft. Every citation must pass the verifier, the value must be whole words of a verified excerpt, and the field lands `needs_confirmation` with the excerpt as its source and the note "Drafted by the agent from the evidence. Check the source and confirm it." `PATCH /cases/{id}/form-draft/fields/{key}` and `PATCH /gaps/{id}` with `value` now save a field the same way: a changed value keeps only the sources whose excerpt contains it; the agent's note is removed on a save; emptying a drafted field sets the note "The caseworker cleared the agent's draft. The agent will not fill this field again."; reopening a gap empties its field's sources with its value | A run left every Form J field `missing` even when the lease had the answer; a value saved on the Missing info page sat next to the agent's quote of a different value |
| 37 | The caseworker can edit the request to the tenant (issue #48). `POST /gaps/{gap_id}/tenant-request` takes an optional body `{ message, message_en }` (trimmed; `message_en` 1 to 1500 characters, `message` 1 to 3000, since a translation can run longer than the English); without it the agent's draft is sent as before. New endpoint `POST /gaps/{gap_id}/tenant-request/translate`, body `{ message_en }`, returns `{ message }`: one model call translates the English into the case's tenant language and nothing is saved (an English-speaking tenant gets the English back, with no call). Both check the text like the agent's drafts: a quotation must be in this case's evidence, no 30+ characters copied from it without quotes, a non-English `message` must be in the tenant's language (and script), and "<" is refused. A bad body or a refused text answers 422 `{ detail: { reasons } }`; another org's gap 404; a resolved or dismissed gap, or one with no draft, 409 (a request already sent can still be corrected); no usable model 503 `{ detail: { reasons } }`; more than 20 translations a minute from one client 429. An edited request is saved on the gap, the activity log says "Edited the request to the tenant", and the gap keeps the agent's first draft for the record (not in the API). `IntakeView.requests[]` gains `message_en`, so the tenant page can show the English as well. | The agent's wording was final: a wrong or unclear request could only be cancelled. The English copy lets the tenant, or someone helping them, check the translation. |
| 38 | `Intake` gains `qr_svg` (a string, or null; issue #56): the QR code of `url` as an SVG data URI (it starts with `data:image/svg+xml`; segno writes `data:image/svg+xml;charset=utf-8,` and the percent-encoded SVG), made on the server with `segno` at error-correction level M. Like `url`, it is set only in the `POST /cases/{case_id}/intake-link` response and is `null` on every GET; it encodes the link and nothing else. New setting `FORWARDED_ALLOW_IPS` (issue #58, default `127.0.0.1`): the proxies whose `X-Forwarded-For` and `X-Forwarded-Proto` the API believes, so the rate limits count each visitor's own IP. | The tenant opens the link on a phone; scanning it from the caseworker's screen saves sending it some other way. The raw token exists only in that response, so the QR has to be made there. Behind a proxy every visitor otherwise shares the proxy's rate-limit budget. |
| 39 | `GET /healthz` checks that Postgres and Redis answer. Both: 200 `{ status: "ok", llm_mode }` as before. Either one down: **503** `{ status: "degraded", llm_mode }`. Which one failed is logged by the API (`healthz: degraded (db=ok redis=error)`, once per change) and never returned, and the result is stored for 5 seconds | A readiness check for `docker compose`, the auto-deploy and any load balancer must cover both dependencies (WS2, from YCL0609's `m2-deploy` branch). The endpoint is public and needs no login, so it says little and stays cheap |
| 40 | Text in images is read by OCR on the server (#61, RapidOCR; settings `OCR_ENABLED`, default true, and `OCR_REQUEST_SECONDS`, default 40). A photo (JPG, PNG, HEIC) with text gets a second `evidence_page`, locator `text in the photo (OCR)`, after its capture-time page. A PDF page with almost no text layer (under 20 characters; at most 10 pages per PDF) is read from its image and its locator becomes `page N (OCR)`. Lines the engine is not sure of (under 0.9) are dropped, so Russian and Hindi text, which it can't read, gives no page. When one upload request has spent its OCR time (reading, or waiting while another upload reads), later images are kept without their text and `EvidenceItem.error` says "The text in this file was not read: the server's time for reading images in this upload ran out. The file is kept as it is." (`processing` stays `done`). No field changes; the model still never receives an image | Screenshots of messages and photos of notices are common evidence, and scanned PDFs had no text, so the agent could cite neither. OCR on the server keeps the images off the model and the network (the vision and content-check parts of #61 stay after the MVP) |
| 41 | `RunStep.status` gains `incomplete` (issue #119): the step ended at its tool-call, token or model-call limit, at the model's output limit, or at the run deadline. `summary` says why. It counts as finished, so a resumed run does not run it again; after a limit the next steps still run, after the deadline they stay `pending`. A run with an `incomplete` step ends `needs_review` (no new `Run.status`) and still counts as completed for the package and the brief. **Warning text**, the same in the case brief, `evidence_manifest.pdf`, `manifest.json` and the Package page: if the timeline step is `incomplete` or still `pending` (it never ran), "The analysis stopped early: the timeline may be missing events. Run the analysis again before relying on this."; otherwise "The analysis stopped early: some results may be missing. Run the analysis again before relying on this."; then `Stopped early: <step labels>`; then, only if there are any, `Not run: <step labels>` for the steps still `pending` after the first `incomplete` step (left out while a step is `running` or `needs_input`). The brief starts with it. `manifest.json` gains `analysis_incomplete` (boolean, always there) and `incomplete_steps` (labels, always there), and the warning lines go in `notes`. All of this reads the case's latest run. The package is not blocked: running again may not help on a large case until #118 is fixed. The brief's "N items need caseworker verification" and its checklist now also list every open gap and every timeline event flag it prints. Runs stored before this change keep their `done` steps | A step that stopped early showed a green "Done", and the brief said nothing was flagged while it listed open gaps |
| 42 | A `.txt` upload that is not a chat or message export (issue #125) gets `EvidenceItem.kind` `letter` instead of `messages`, `format_check.note` "Digital documents must be Word, Excel or PDF (Evidence Policy #42). The package adds a PDF copy." (`accepted` true, `action` still `will_export_pdf`), and `evidence_page` locators `line 1`, `line 2`, ... instead of `message 1`, `message 2`, ... (one per non-empty line, as before). A chat keeps `messages`, its note and `message N`: more than half of its non-empty lines start with a speaker (`Name:`, `名字：`; not `To:`, `Date:`, `Re:` or similar letter headers) or are timestamped where chat exports put the timestamp (a date or a time at the start of the line, after an optional `[`, or a line that is only a name, a date and a time, as in a WeChat PC export), or at least 3 lines are timestamped. A date or time inside a sentence (`On 2026-08-14 I reported ...`, `... at 9:30 pm`) does not count. A tenant's typed answer on the intake page is always `messages`. A TXT that can't be read keeps `messages` and its note. The package files a letter like a chat: the TXT and a PDF copy. No field changes and no migration: stored evidence keeps its kind, note and locators | A letter typed as a TXT was cited as "message 1…N" and told the caseworker text messages must be submitted digitally or printed; Evidence Policy #42 page 4 asks for digital documents in Word, Excel or PDF |
| 43 | New `GET /cases/{case_id}/package/files/{filename:path}[?version=N]` (issue #91): downloads a single file from a built package zip. Default `version` is the latest. Matches `filename` by exact, case-sensitive lookup in that version's `files` list and reads only the matched member from the stored zip (never the request string as a path); any other name, unknown version, missing package, or another org's case answers 404 (401 when signed out). Verifies the member's SHA-256 against the entry's `sha256` (500 and a warning log on mismatch). Headers: `Content-Type` (`mimetypes` guess, fallback `application/octet-stream`), `Content-Disposition: attachment; filename="<last path segment>"`, `Content-Length`, `Cache-Control: private, no-store`, and `X-File-Sha256`. Not logged in the activity log | The Residential Tenancies Program does not accept zip files; letting the caseworker download each file directly avoids unzipping the package on a shared clinic PC while keeping the zip as the record |
| 44 | PDFs now draw Devanagari with text shaping (issue #68: `uharfbuzz`, fpdf2 `set_text_shaping` with script `deva`, turned on only for paragraphs that contain Devanagari). For a case whose language is `hi`: the `[Hindi text, see the original file]` marker is gone; the line `PDFs are in English; Hindi PDF rendering is not supported yet.` is gone from the evidence manifest PDF, the case brief and `manifest.json` `notes` (`notes` now holds only the analysis warning, and is omitted when empty, as for other languages); and a Hindi TXT file gets its `evidence/E-NN.pdf` copy again. This supersedes the Hindi part of the implementation note on Russian and Hindi | Hindi tenants' evidence and names were missing from every PDF |
| 45 | Personal details out of the model's view (issue #60). New setting `PRIVACY_PLACEHOLDERS` (default false). New table `privacy_term` (migration `5f1d3c7a9b20`): a caseworker's `hide` or `show` choice for one value of a case, unique per case and casefolded value. New endpoints `GET /cases/{case_id}/privacy`, `POST /cases/{case_id}/privacy/terms`, `DELETE /cases/{case_id}/privacy/terms/{term_id}` and `GET /cases/{case_id}/evidence/{evidence_id}/model-text`, with the shapes `PersonalDetail`, `PrivacyView`, `PrivacyTermCreate`, `ModelTextPage` and `EvidenceModelText`. See "Personal details and the AI model" in `API_CONTRACT.md`. | Clinics should not have to send tenants' names, addresses and numbers to a model provider to get a timeline; the quote check and the filing still need the real text |
| 46 | `POST /cases/{case_id}/translate-excerpt` (#171): drops the ASCII-only short-circuit; an excerpt is returned unchanged only when the language is `en`. Any excerpt in a non-English case (ASCII or not) is translated; the prompt tells the model to return a quote already in English verbatim. | French and Spanish chat text often has no accents, so valid non-English quotes were skipped by the ASCII check |
| 47 | New `GET /cases/{case_id}/package[?version=N]` (#200) returns the `Package` of the latest build, or of `N` (`N >= 1`), with the same version query as `GET .../package/download`: 404 for another org's case, no built package or an unknown version, 409 for landlord cases, 401 when signed out, 422 for a version below 1. It sends `Cache-Control: private, no-store` and adds no activity entry, since reading changes nothing. | The Package page lost its contents and its file links on reload or case switch because no endpoint read a built package back |
| 48 | Resuming a paused run (#163, PR #208) keeps its placeholder numbering in `steps[0]` while a checkpoint exists (dropped when the run finishes, never returned by the API) and returns 409 if `PRIVACY_PLACEHOLDERS` differs from when the run began (runs saved before the flag skip the check). Form J chronology (#196, PR #207): `PATCH /cases/{id}/form-draft/fields/{key}` and `PATCH /gaps/{id}` with a `value` return 422 `{ detail: string }` when a new `move_out_date` is earlier than `move_in_date` or a new `fixed_term_end` is earlier than `fixed_term_start` in either edit direction; equal dates, blank counterparts, and confirming an unchanged stored value stay allowed; legacy reversed pairs are flagged in the draft UI and generated PDFs; notice dates stay unordered on the server with a non-blocking UI warning. | Renumbering placeholders mid-run could map one value to two tokens or leak real values after a setting flip; reversed tenancy/fixed-term dates produced contradictory drafts |
| 49 | Idempotent case creation and cheap case loads (#202, #218). `ApplicantCaseCreate` gains optional `idempotency_key` (1 to 64 characters matching `[A-Za-z0-9._:-]+`); `tenant_case.idempotency_key` stores it (migration `a7c4e19b2d63`) under a partial unique index `uq_tenant_case_org_idempotency_key` on `(org_id, idempotency_key) WHERE idempotency_key IS NOT NULL`, so keys are scoped per org and rows without one never collide. `POST /cases` looks the key up before creating and returns the existing `Case` (200) without a second case, form fields or "Created the case" line; a unique-index race is caught and resolved the same way. A 422 (bad body or a refused value) is answered before any lookup or write, so it binds nothing. Additive `Case.has_run` and `Case.has_package` booleans say whether the case has any run and any built package; `GET /runs/latest` and `GET /package` keep their 404/409 answers and are simply not called when the flags say there is nothing. Both fields default to `false`, so the schema lands without the routes that fill them. | A retry after a lost success response made a duplicate case; every case load asked for a run and a package that did not exist yet, which Chromium reports as failed requests even when the page handles the 404/409 |

## Implementation notes
- M0's `DEV_STUB_AUTH` is removed in M1. Seeds create two orgs with one caseworker each (`sam@example-clinic.test`, `jo@harbourside-clinic.test`); passwords come from `SEED_PASSWORD` (compose default `tenantproof-demo`, local only).
- PDFs use bundled Noto Sans (Regular, Bold) and Noto Sans SC (Regular), SIL OFL, in `backend/app/assets/fonts/` (sha256 in `FONTS.md`), so Chinese renders.
- Seeding: `python -m app.seed` loads data only into an empty database, so `docker compose up` never wipes work. `--force` (used by `make seed`) wipes and reloads; `make reset` drops the dev database, migrates and reseeds. The blob volume is not touched by either.
- Process: the timeline, gaps and form routers were written by the main session instead of `scaffolder` (the spec was as long as the code). `scaffolder` wrote only the Electron shell; `test-writer` wrote the tests, which the main session audited.
- `desktop/main.js` also blocks off-origin `will-redirect` (the scaffolded version only blocked `will-navigate`).
- The UI page is served with `Cache-Control: no-cache` so a changed `index.html` is never stale.
- Compose adds a named volume `blobs` mounted at `/data/storage` (`STORAGE_DIR`) for package zips.
- CI runs a Redis service and the tests use it for rate-limit counters (`RATE_LIMIT_STORAGE_URI=redis://localhost:6379/1`); there is no in-memory fallback.
- M1 zip contents: `application_draft.pdf`, `evidence_manifest.pdf`, `manifest.json`. Evidence files join the zip in M2.
- M2 zip: each stored original is added as `evidence/E-NN.<ext>`, named from the exhibit label, never the uploaded filename. HEIC also gets `evidence/E-NN.jpg` and TXT gets `evidence/E-NN.pdf`, made at build time, because the tribunal takes neither format (the `format_check` notes say "The package adds a JPG/PDF copy"). `manifest.json` evidence items gain `in_zip` (the original's zip path, or null when its bytes were never stored, as for seed data) and `rendition` (`{ path, sha256 }` or null). Package `files` lists only what is in the zip. Originals and the HEIC-to-JPG copy keep their EXIF, including GPS, because they are the filed evidence. The stripped copy (`stripped_sha256`, `ingest.model_safe_blob()`) is the only image data that may go to the model; documents go as their `evidence_page` rows.
- M2 evidence processing runs during the upload request, one file in memory at a time and with no database connection held: type check, metadata (capture time, GPS present, device, software), where `software` names editing software only: the EXIF Software tag is dropped when it is a camera app or firmware (iOS writes its version, ProCamera and Halide their names, Samsung its firmware, Pixel "HDR+"), so a plain phone photo doesn't look edited. Then a stripped copy of photos (`stripped_sha256`, pixels only, at most 4096 px on the long side, HEIC to JPEG; images over 60 MP end as `failed`), and text written as `evidence_page` rows (#6): one per PDF page (`page 1`, `page 2`, ...) and one per non-empty line of a TXT file (`message 1`, `message 2`, ..., the locators the seeded timeline cites). PDF limits: at most 300 pages, 1M characters and 10 s per PDF, a content stream shared by many pages parsed once, `error` says when it stopped early. The 10 s is checked between pages, so pypdf runs in a child process that is killed at 15 s (a fork server on Linux, spawn on Windows; on Linux the child is also capped at 2 GB of address space and 20 s of CPU); a killed parse ends as `failed`. TXT is accepted as UTF-8, UTF-16 with a byte-order mark, or GBK/GB18030 limited to simplified-Chinese (GB2312) characters, since Windows-1252 English or French and Shift-JIS also decode as GBK and would be filed garbled; those answer 415 (re-save as UTF-8). The original bytes are stored as sent. A HEIC or TXT that ends as `failed` gets no JPG/PDF copy in the package, so its `format_check` says so (`accepted: false`, `action: "none"`, the note asks for a JPG) instead of promising one. A file that can't be decoded is kept with `processing: "failed"` and the error type is logged. Rows are then inserted under a short `FOR NO KEY UPDATE` lock on the case. Background processing comes with the WS3 worker.
- M2 known gap: blobs are written before the transaction commits, so a failed request can leave unreferenced originals (with GPS) in `STORAGE_DIR`. Storage is content-addressed and shared between rows, so a sweep must check every reference first. Not done yet.
- M2 file types are checked by signature in `services/evidence/sniff.py`, not python-magic as `docs/NEXT_PROMPTS.md` first said (WS1's PR updates it): python-magic needs the native libmagic, which fails to import on Windows (`ImportError: failed to find libmagic`) and AGENTS.md forbids system-wide installs. The Dockerfile needs no libmagic either.
- Postgres host port is `POSTGRES_HOST_PORT` (default 5433). The Makefile (`up`, `down`, `test`, `lint`, `seed`, `link`) uses `docker compose` if available, else `docker-compose`.
- The four summary-only cases get placeholder gap/event rows so their counts are real. `seed_data.json` marks them `synthetic_placeholder_rows: true` and the rows are titled `[Synthetic placeholder] ...`.

- Source check of the WS4 legal sources (fix/legal-sources). `Case.next_deadline.label` is now `Must be received by · hearing <ISO date>` instead of `Evidence due · hearing <ISO date>`: the date is when evidence must be *received* (Regulations s. 25A(2)), and mail counts as received 3 days after it is sent, e-mail sent after 4 p.m. the next day (s. 25A(3B), (3C)). The date math is unchanged. The filing package no longer contains a `.heic`: a HEIC is filed only as a JPG made from it (`evidence[].in_zip` is the JPG, `rendition` is null), and a HEIC that cannot be converted is left out and said so in the manifest PDF (the Program does not accept HEIC, Policy #42). UI: the package note and the package reminders say the zip is for the caseworker's records and that the Program does not accept zip files; `web/index.html` mock labels follow the new wording.
- Filing package privacy: every image in the zip (JPG, PNG, and the JPG made from a HEIC) is a copy with its GPS data removed; the capture time (DateTimeOriginal) and orientation are kept and the stored originals are not modified. `manifest.json` evidence entries gain `location_data_removed: boolean`; for such a file the `filename`'s `sha256` in `files` is the hash of the copy, while `evidence[].sha256` stays the hash of what was received. An image whose location cannot be removed is left out (`in_zip: null`) and the manifest PDF says so. Caseload priority reason, the rules-step summary and activity log, and the mock UI now say "Must be received in N days" / "must be received by" instead of "Evidence due"; no date math changed.
- Submission polish (`Lameda12/submission-polish`). Every answer, API and UI, now carries `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` and `Referrer-Policy: strict-origin-when-cross-origin` (no Content-Security-Policy). `CaseSummary.priority_reason` says "Deadline passed (N days ago)" for a past deadline and "Must be received today" on the day, never a negative count; counts are pluralised. `CaseSummary.next_deadline.label` is returned in the current wording ("Must be received by · hearing <date>") even when the stored label says "Evidence due". Seeded demo deadlines store `demo_offset_days` inside the stored `Case.next_deadline` JSON (not part of the API shape), and are read as that many days from today, so a database seeded days ago never shows a past deadline. API_CONTRACT gains `POST /auth/login`, `POST /auth/logout`, `GET /cases/{case_id}/package/download`, and the form-draft PATCH path is `/cases/{case_id}/form-draft/fields/{key}`. - Tenant Form J F1–F3 (issue #67, [implementation PR #143](https://github.com/opoeci6/TenantProof/pull/143)). This entry describes the behavior once #143 ships. `GET /cases/{id}/form-draft` keeps the response shape and projects 67 optional caseworker fields alongside the seven standard fields for a prepared draft (74 total). An entirely empty form still returns no field entries. The new keys cover F1 parties' civic and mailing addresses, phone numbers and email, applicant email consent, and the rental premises address. F2 adds distinct move-in and move-out dates, notice details, written lease and term, weekly rent, copies and security deposit. F3 adds independent tenant request selections with reasons, including the two payment sub-options. Existing field keys, stored values and citations carry forward without a migration. `PATCH /cases/{id}/form-draft/fields/{key}` accepts the optional keys and writes existing PostgreSQL `form_field` rows on demand with a conflict-safe insert on `(case_id, key)`. Reading the draft does not create rows. Saving only optional entries leaves the case eligible for the agent to initialize the core form fields.
- F2 alternatives affect requirements. A saved `weekly_rent` makes `monthly_rent.required` false, and a saved `move_in_date` makes `tenancy_start.required` false. Required counts, stage, package gating and deterministic gaps use those effective requirements. Saving an alternative resolves an existing open or waiting gap for the legacy field. Clearing it reopens a gap closed by the alternative if the legacy field is still empty. `PATCH /gaps/{id}` returns 422 when asked to reopen a covered resolved gap. The form PATCH also returns 422 with a plain `detail` string for a new malformed email, CAD amount, choice, date or request flag, or for a nonempty rent write while the other period has a value. The [Form J draft fields](API_CONTRACT.md#form-j-draft-fields) contract lists the accepted values. `list_form_fields` hides the optional and currently covered keys, and `fill_form_field` and `create_gap` refuse those keys. The existing tenant remedy remains caseworker-entered.
- `application_draft.pdf` keeps the partial-draft title and includes grouped F1 contact and address details, applicable F2 lease fields, and the selected F3 requests and their reasons. The applicant email is printed only on explicit consent. Unselected requests and payment sub-options under an unselected payment request are omitted. Valid amounts are printed in CAD. The draft asks the applicant to sign and date the official Form J. It covers tenant requests. The official F4 section applies to landlord applicants.

- Form J applicant roles (issue #67). This behavior starts when [implementation PR #154](https://github.com/opoeci6/TenantProof/pull/154) ships. `ApplicantCaseCreate.applicant_role` accepts `tenant` or `landlord`, defaults to `tenant` when omitted, and is returned on `Case`.
